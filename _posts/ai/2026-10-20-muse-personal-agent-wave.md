“帮我持续盯着这件事，有变化再告诉我。”

这句话让我觉得兴奋，因为它对应的是一种更省心的工作方式：你交代目标，AI 记住进展，有新信息就接着办，到了需要你决定的地方再回来找你。每天从头解释一遍的日子，实在太费劲了。

Meta 推出的 Muse，把这样的承诺带进了个人生活。对经常在邮件、日历和各类网站之间切换的人来说，吸引力很具体：有些琐事终于可以交出去，而且不用每天重新交代一遍。

我看个人 Agent，就看任务交出去以后，人能不能少操心。上周交代的偏好它记得住，今天做到哪一步它说得清，遇到需要我拍板的事它能及时递回来。这样的体验，才值得长期留下。

## Muse 把怎样的 AI 带到了用户面前

Meta 在 2026 年 9 月 8 日发布 Muse，首发从美国的 iOS、Android 和网页端逐步开放。按照[首发公告](https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/)，它有自己的云端电脑和浏览器，可以跨应用处理任务，应用关闭后仍可继续工作，并在发邮件、购买等动作前请求用户确认。

Muse 是个人 Agent 产品，Muse Spark 是底层模型。模型负责的能力，和产品里的状态保存、服务连接、执行检查，要放在一起看。这里让我感兴趣的，正是它们开始围绕一整件事配合工作。

10 月 12 日，Meta 又公布 Muse Wonder 与 Wonder Full，把持续记忆和长任务执行列为重点。开发者 API、Muse Code 和个人 Muse 产品各有接入安排，个人产品按后续计划逐步接入。[Muse Wonder 公告](https://about.fb.com/news/2026/10/introducing-muse-wonder-models/)把这条路线说得很清楚：模型能力正在围绕更长的任务生长。

我更愿意用持续几天、几周的任务来评价这条路线。工具会断，账号会过期，人也会改主意。系统怎样把这些变化接住，比一场顺滑的演示更能让我建立信任。

## 个人 Agent 浪潮里，竞争的任务变长了

同一时期，9 月 29 日，OpenAI 发布 dots，介绍配备云端电脑、可以后台工作的长期 Agent，从符合条件的套餐和市场开始开放。[官方公告](https://openai.com/index/introducing-dots/)强调持续了解用户、接入工作工具，并把进展和需要批准的动作交还给人。

同一天，Meta 发布 Muse for Small Business，把业务工具与新技能接入 Muse，并在公告中列出 Shopify、Canva、Slack 等连接器。[小企业版本公告](https://about.fb.com/news/2026/09/introducing-muse-small-business/)显示，个人生活和小团队工作正在成为相邻的产品场景。

这些产品值得一起观察，因为它们接手的工作跨越了多次对话。用户今天交代目标，明天补充限制，后天收到变化，任务仍然需要接着做。一个人同时有家庭安排和客户项目，产品还得分得清两边的资料、权限与优先级。

因此，评价单位也该跟着调整。一次回答写得漂亮，只能说明那次回答。持续一周的任务，需要看中间有没有遗忘、重复操作和误解，也要算上用户为了纠正它花掉的时间。

长期使用最有意思的变化，是人会改主意。上周的标准，今天就能被新要求替换。让系统及时跟上，比反复展示它记住了多少旧信息更有用。

## 用一件小事，拆开它应该完成的工作

假设一位关注 AI 的读者交代：“每周五帮我整理值得看的模型与产品更新，尽量用官方来源，重复消息放在一起，先给我看草稿。”

就拿这份周报来说，系统要把几类信息分别记住：

| 需要保存的东西 | 在这个例子里意味着什么 |
| --- | --- |
| 长期偏好 | 更关心模型上线和产品变化，少收重复宣传 |
| 本周状态 | 已查过哪些来源，哪些事实还没有核实 |
| 输出标准 | 保留真实日期和链接，区分预览与正式可用 |
| 行动边界 | 可以整理、起草，发布前交给用户审阅 |

“已经找到十条消息”和“这期周报可以交稿”之间，还有一段工作。系统要识别同一公告的转载，检查发布日期，发现标题说“上线”而正文仍是等待名单时保留差别。遇到无法确认的消息，还应该保留疑点，给出需要继续核实的地方。

这些分散、重复、需要来回核对的步骤，正适合交给个人 Agent。读者把精力留给选题与判断，系统负责把资料整理到能审阅的程度。省下来的注意力很实在。

如果每条消息都要重新查一遍，那就是把复制粘贴换了个界面。我的评价标准很直接：完成了多少，返工了多少，最后审稿又花了多久。这几项放在一起，省不省心一眼就能看出来。

## 持续记忆需要允许用户修改

Muse 的设计说明介绍了跨对话记忆、可以直接查看和编辑的记忆文件，以及管理长期目标的界面；后台结果也需要判断是否值得打断用户。[官方设计说明](https://introducing.muse.ai/)讨论的这些安排，比一个拟人化头像更影响长期使用。

记忆要能跟着人改。还是周报这个例子，用户说“这周先少看融资消息”，这就是当周要求。把它存成长期偏好，后面的选题就会越跑越偏。临时要求和长期习惯，得分开放。

好的记忆至少要区分长期偏好与临时要求。用户应该能知道一项判断从哪里来，改掉它，并让后面的任务采用新版本。涉及工作、家庭等不同场景时，还需要让信息停留在合适的范围里。

任务状态同样要清楚：资料待核实、草稿等审阅、文章已发布，分别对应不同的下一步。读者自己接手做完以后，系统也该马上跟上进度，免得同一件事又做一遍。

对用户而言，可查看、可修正的记忆和状态，是减少沟通成本的工具。没有这些，所谓“越用越懂你”很难检查，出错时也找不到该改哪一处。

## 服务能否接通，决定许多任务能走多远

想让 Agent 帮你完成退货，它得能读取订单、进入账号、调用商家允许的操作。找到退货说明，只是流程的开始。连接能走到哪一步，决定这件事最后还需要你亲手处理多少。

10 月 6 日，Sierra 宣布与 Meta 等公司推进 Personal Agent Protocol，让个人 Agent 与企业围绕身份、授权和交互建立共同方式。10 月 9 日发布的 Poppy 草案继续明确：用户授予访问权，企业提供操作通道。[协议公告](https://sierra.ai/uk/blog/introducing-personal-agent-protocol)与[草案说明](https://sierra.ai/blog/poppy)记录了这一步进展，后面就看具体服务怎样接入。

它试图解决的问题很实际：企业怎样知道这个 Agent 代表谁，能读哪些内容，能改哪些订单？遇到需要协商的事情，双方能不能保留同一次任务的上下文？

服务接入共同协议以后，Agent 就能直接使用企业提供的操作通道。还没接入的地方，继续通过网页与现有接口完成流程。连接器、登录与页面维护，也因此成为产品长期要做的工作。

对接服务、维护连接器、处理异常，是个人 Agent 产品持续要做的工作。我选这类产品，会先看它接通了哪些常用服务，再看一笔订单、一封邮件究竟能替我处理到哪里。

## 用户授权需要跟得上任务变化

让 Agent 少打断人，是合理目标。把每个步骤都变成确认弹窗，最后只会让用户疲于点击。但用户也需要看清，那些批准究竟覆盖什么。

Muse 的技术文档把执行 Agent 与独立的 Sentinel 权限判断分开，后者负责判断外部动作的许可。当前使用 Secure VM，Confidential VM 则列在后续计划里。[技术说明](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse)中，我最关心的是授权怎样落实到每个动作，以及数据在当前架构下怎样受到保护。

我希望批准卡把事情讲得一眼就懂：对谁做什么，涉及哪些内容，允许一次还是持续有效。整理邮件与向外发送附件分别呈现，用户就能快速做决定。

任务变了，批准卡也要跟着更新。周报原本只在本地起草，后来要发给合作方，系统就把收件人和分享范围摆出来。用户看一眼就能决定，比自己追查它到底要发给谁轻松得多。

允许系统继续执行和允许用户随时接手，同样重要。中途暂停以后，它应该说明完成了什么、还有什么没做，以及是否已经产生外部影响。这样，人接回任务时不需要重新调查一遍。

## 商业价值要和人的注意力一起计算

我对个人 Agent 最直接的期待，就是少操心。后台动作做得再多，最后仍要我逐条重查，这件事就没有真正交出去。

一份周报整理准确、来源清楚，读者只需决定哪些值得展开，这就很舒服。每天塞来一堆提醒，还得自己去重、筛选、关通知，反而把后台工作变成了前台负担。

没有新进展时，我希望它安静工作；出现影响目标的变化，再把证据和下一步送过来。频率自己能调，任务随时能停，这些细节做好了，持续运行才让人舒服。

成本还包括服务订阅、计算消耗与失败重试。一次任务模型调用便宜，无法单独说明整周运行便宜；同样，一份结果生成很快，也无法说明用户审阅它很轻松。

我最看重的指标，是完成一类重复任务后，人到底少操心了多少。系统做过的事看得见，需要人决定的地方递得回来，这样的后台工作才让人轻松。动作数量再漂亮，也得落到节省了哪段流程上。

## 个人 Agent 也在争夺日常服务的入口

当用户先把目标交给 Agent，服务入口就开始前移。找餐厅、选商品、处理退货，一部分准备工作发生在打开原应用之前。我的判断是，商家接下来得认真对待“Agent 怎样找到我”这件事。

对商家来说，顾客第一次筛选正在增加一个新入口。Agent 帮人找聚餐餐厅，要比较位置、价格、饮食限制，还得拿到最新资料。谁的信息清楚、服务好接，谁就更容易进入这次选择。

看图片、比较细节、拍板决定，用户依然会打开原产品。但前面的准备工作交给 Agent 以后，商家就要让新入口准确呈现自己，再把推荐接到实际服务。Poppy 这样的尝试，解决的正是双方怎样相互识别。

长期记忆也在增加迁移成本。聊天记录是一份文本，进行中的目标、已经核实的资料、获准执行的动作，却是一整套工作状态。一个系统熟悉了你的做事方式，换到另一个系统，就要考虑这些进度怎么带走。

所以，查看和导出数据只是起点。用户能否结束一项长期任务、撤回授权、带走成果，并清楚知道还有没有后台工作，也是产品能否被放心使用的一部分。

我更看好个人 Agent 承接越来越多日常任务。工作和生活有不同账号，也有不同规则，几个专长系统协同同样很自然。谁把高频任务做得顺，谁就更值得用户持续交付工作。

## 先从一件能复查的小事开始

对普通读者，试用个人 Agent 可以从范围清楚、结果容易核对的事情开始：整理固定来源的更新，检查某类日程冲突，或为重复出现的工作准备草稿。

开始前，把周报的条数、来源、去重规则、交稿时间和审阅步骤写清楚。跑过几次真实任务，再把稳定的要求存成长期偏好，每周变化的安排留在当期任务里。用着用着，才会越来越省事。

随后观察四件事：任务有没有做完，错误能否被发现，纠正后会不会再犯，以及中断后能否接着做。记录实际用时，包括自己解释需求、审阅和返工的时间。这样的结果比一段流畅演示更能帮助选择产品。

对做产品的人，也可以先选一种用户经常遇到的完整任务，把进展、失败和交接做清楚。用户会逐渐建立对它的判断：这类事可以交出去；遇到什么情况，需要自己回来处理。

Muse 让我对个人 Agent 多了期待。接下来我最想看的，是用户几周后还愿意把哪些事交给它：任务变了能接着做，偏好变了能跟着改，需要人决定时又能及时把进展送回来。做到这些，AI 才真正走进了日常。
