## 历史相册

覆盖四个目录内148张源照片，预览宽度为640/1280px、WebP质量80。全部源照片约146.47 MB；大预览合计23.65 MB，小预览7.56 MB。所有原照片字节不变。

`_data/optimized_images.json` 记录源 SHA-256、原始字节数、预览路径、尺寸与体积。`_plugins/optimized_images.rb` 在 Jekyll Markdown 转为 HTML 后替换已登记照片：

- 通过 `srcset` / `sizes` 选择预览，并声明宽高，提前预留图片位置。
- 每篇第一张照片立即加载，后续照片用浏览器原生 `loading="lazy"`，不依赖 JavaScript。
- 为没有链接的照片提供原图入口，保留已有链接与作者显式指定的响应式图片。
- 不改历史 Markdown、标题、日期、旧页面地址或旧图片地址，不处理未登记的图表、截图与外链图片。

本机 Chromium 实测：1440px桌面首屏请求4–5张预览，390px手机首屏请求7–10张预览，均未在首屏请求相册原图。浏览器会提前加载视口附近图片，因此懒加载不等于只加载当前可见的一张。滚动至最后一张可以正常显示，原图链接可用；无 JavaScript 时仍可浏览。

## 维护与验收

预览是已提交资源，正常 Jekyll 构建无需 Python、Pillow、原站 API 或后端。维护者需要重生成时，在具备 Pillow/WebP 编码能力的 Python 环境中运行：

```sh
python3 scripts/optimize_images.py
```

背景原图从已安装的锁定版 Hydejack gem 读取。源照片修改后，预览文件名会随源内容哈希改变。新增其他相册须显式加入脚本的目录清单，再重生成映射与图片。生成目录仅存放此脚本管理的预览；旧版本遗留预览在确认不再引用后再清理。

使用 README 要求的 Ruby 3.3+ 环境进行验收：

```sh
JEKYLL_ENV=production bundle exec jekyll build --trace
bundle exec ruby tests/optimized_images_test.rb
python3 scripts/verify_migration.py
python3 scripts/verify_huangdao_import.py
git diff --check
```

本轮实际使用 Ruby 3.4.8 完成生产构建、渲染插件边界测试、337个原内容源及92个旧网址检查、20篇迁入文章验收。未删除或弱化历史验收断言。148张照片的源哈希、296个预览候选在产物中的一致性均已核对。

浏览器检查包括桌面/手机的首页、联系页、个人文章与四篇相册，图片及目录不横向溢出，滚动加载和点击原图通过。两个二维码的压缩资源及桌面/手机渲染截图均经 Vision 解码确认。只测本地图片行为时屏蔽了第三方统计请求，截图中的外部计数器占位不代表图片优化修改了统计服务。

验证证据存于被忽略的 `.migration-work/image-optimization/`。本轮没有测量线上压缩后的真实耗时；此前小文件的首字节等待也偏慢，图片缩小会降低传输量，但不代表已解决 GitHub Pages 的访问链路延迟。
